# moodle-handoff

Deliver the artifact resource or exported .h5p file with title, objective, instructions and dependencies. Explain which structure/semantics/importation checks passed. Report playback and grading as not_run unless actually exercised. Have the teacher verify feedback, scores, retry, accessibility and mathematics in their Moodle.


For a content-only package, give the required library versions. When the report lists missing local libraries, semantic validation is still pending. If a current destination profile is available, pass its target_profile_id to the validation tool and report any missing target libraries. The comparison uses declared major and minor versions. An empty list does not establish Moodle playback or grading. For a package with libraries, distinguish successful local validation from a successful import observed in Moodle.

For a density prediction, the point may record the choice of equal densities. Ask the learner who chose double to calculate the mass of one cubic centimetre in each sample. Assess their explanation separately. For a numerical blank, tell the teacher which decimal variants you actually tried and the score they produced.

For each reported failure record the package hash, Moodle and library versions, browser, role, input, expected result and observed result. Test the actual focused text after checking a blank, and both the visible score and live region after a partially correct weighted set. Record a screen reader observation separately from a DOM check.

Inspect `Library runtime:` warnings from preparation, compilation, export and package validation. They identify tested script bytes by SHA-256. For content-only packages the inspected runtime is the local library installation; for full packages it is the embedded library. Ask the destination administrator to verify the effective served script and evaluate a maintained update when a warning applies. A different script hash leaves runtime behavior unverified. Keep experimental host patches explicit and outside activity generation.

Record `student_attempt`, `persistence`, `accessibility` and `mobile` independently from structure, semantics, importation, playback and grading. Older saved reports can omit these fields; treat that evidence as unavailable. Local generation initializes destination checks to `not_run`. Scope each actual observation to the package hash, runtime, role and environment.
