# H5P MCP 0.2.0

This release adds authoring feedback and Windows support for Docker Engine in WSL, and includes Moodle QA corrections, storage/archive hardening and faster library discovery since v0.1.0.

## Features and fixes

- Optional hints for multiple-choice answers and previews of internal scores for pinned question types.
- Reject identical choices with contradictory answer keys; report known runtime findings consistently across authoring paths.
- Correct overall feedback, Spanish navigation and QuestionSet score labels; provide Moodle host patches and reusable authoring/accessibility guidance.
- Bound ZIP path indexing; inspect and extract the same private archive; publish verified library directories atomically.
- Apply preparation quotas before copying, deduplicate asset aliases, retry store initialization and renew automatically selected expired snapshots.
- Bound physical object cleanup and retain idempotency tombstones separately; recover abandoned writer locks without stealing live leases.
- Return authenticated download links for artifacts that exceed the inline HTTP response budget.
- Discover catalog metadata without copying a full runtime generation. Hash and copy files with bounded concurrency while preserving verification, cancellation and generation identity.
- Run Windows Docker rendering, image setup and cleanup through the CLI in Ubuntu WSL. Docker Desktop is no longer required.

## Upgrade notes

- Windows Docker users must install Docker Engine and BuildKit in Ubuntu WSL, or select another distribution with `H5P_MCP_DOCKER_WSL_DISTRO`. The Windows backend no longer connects to the Docker Desktop pipe. Start the Engine and pull the pinned images in that distribution. Follow the README for figure setup and verified image profiles; images from another engine are not automatically transferred.
- Stop older MCP processes before upgrading an existing object store. Cleanup metadata is migrated automatically. Preserve the source libraries and object store; no manual deletion is required.
- Retain `.core-lock-v2.sqlite` and `.core-lock-v2.token`. The local filesystem must support SQLite locking, hard links and atomic rename. Legacy orphan lock directories require operator verification before removal.
- HTTP clients must support a `text/uri-list` resource response for oversized stored artifacts and use the authenticated artifact download endpoint.
- Existing prepared activities can require preparation again because backend provenance has changed. Preserve their editable source and assets.

## Installation

Download `h5p-mcp-0.2.0.tgz` and `SHA256SUMS.txt` from this GitHub Release. Verify the checksum and install into a dedicated directory with Bun 1.4.4:

```powershell
bun add --ignore-scripts ./h5p-mcp-0.2.0.tgz
bun ./node_modules/h5p-mcp/dist/core/cli.js stdio
```

Configure the MCP client to use that installed entry point and retain its existing data/export directories. Scientific rendering remains optional and requires the documented package, raster and engine setup. This distribution is provided through GitHub Releases, not npm.

## Validation boundaries

Automated checks cover package structure, source compilation, artifact hashes, storage, transports and local Docker sandbox behavior. They do not establish Moodle destination import, playback, accessibility or grade transfer for every activity. First-use library snapshots still incur substantial copying and integrity-check costs.
